# Documentation Audit — May 2026

> Internal backlog. Not part of the published site (kept as `draft: true`).
> Generated against lex-app-docs `content/` tree on 2026-05.
> **Auditor note:** This pass was done against the docs only. The lex-app
> source code at `~/Documents/lex/lex/lex_app/` was not reachable from the
> audit environment, so every claim about "current code behaviour" that
> couldn't be verified from the docs is listed under **Open questions**
> rather than asserted as a finding.

## Executive summary

- **Overall in good shape.** The feature pages, reference pages and tutorial
  share a consistent voice (practical, second-person, no internals leakage
  into feature docs). No "ContextResolver / LIFO stack / error class" jargon
  found in `features/` — that earlier complaint has been addressed.
- **Frontmatter is consistent** across all `content/**/*.md` files except
  one orphan (`content/PFE - Lund User Calculation Permissions.md`).
- **CLI Commands page is the single biggest gap.** Several commands the rest
  of the docs tell users to run (`lex create_db`, `lex streamlit`,
  `lex celery`) are not listed there, and `lex generate-configs` is listed
  with no description.
- **The `workshop/` subtree (6 pages) is orphan** — nothing in the main nav
  links to it — and uses a different spelling convention (British) and link
  style (relative URL-encoded vs. wikilinks) than the rest of the site.
- **Seven `📸 TODO:` placeholder comments are still in published pages.**
  Screenshots and one video reference are missing.

### Top 5 highest-priority fixes

1. Add the missing CLI subcommands (`lex create_db`, `lex streamlit`,
   `lex celery`, full description for `lex generate-configs`) to
   [reference/CLI Commands.md](reference/CLI%20Commands.md). Pipeline keeps
   touching this file, so getting it complete reduces conflict surface.
2. Decide what to do with `content/workshop/` and
   `content/quartz_style_docs/`. Either link them from `index.md` or move
   them out of `content/` so they don't ship as orphan pages.
3. Remove the `PROJECT_GROUPS` forward-reference in
   [tutorial/Part 2 — Data Models.md](tutorial/Part%202%20%E2%80%94%20Data%20Models.md)
   line 558 — Part 4 never actually documents `PROJECT_GROUPS`.
4. Reconcile the contradiction in `running your app.md` (terminal:
   `streamlit run lex_app/streamlit_entrypoint.py ...`) vs.
   `features/access-and-ui/streamlit dashboards.md` (terminal:
   `lex streamlit`) vs. `tutorial/Part 5` (uses `lex streamlit`). Pick one.
5. Sweep the seven `<!-- 📸 TODO: -->` placeholders and either fill them
   or delete them. They currently ship to the published site.

## Style & consistency issues

### Terminology

- **Spelling drift.** `quartz.config.ts` sets `locale: "en-US"`. Site-wide
  the docs use American spelling (`organized`, `organize`, `behavior`).
  The `workshop/` subtree uses British (`parallelisation`, `behaviour`).
  Pick American to match locale.
- **"calculation" vs. "calc"** — both forms appear in feature pages and
  tutorial copy. Consistent enough to ignore, but worth a glossary entry.
- **"model" vs. "project model"** — used interchangeably in feature
  pages. Not actively misleading, but a one-line glossary entry would
  help.
- **"V1" / "generic_app" / "old"** — three names for the same legacy
  framework appear across the migration section. Pick "V1" everywhere
  the heading is user-facing.

### Frontmatter

- All `content/**/*.md` files have YAML frontmatter and a `title:` key
  except `content/PFE - Lund User Calculation Permissions.md` (orphan,
  see Stale content).
- `content/workshop/index.md` has both `title:` *and* a `description:`
  field. No other page uses `description:`. Either standardise on
  including `description:` everywhere or drop it from workshop pages.

### Links and images

- Workshop pages use **relative URL-encoded** links
  (`../getting%20started.md`, `part-1-data-ingestion.md`) instead of the
  Quartz-style wikilinks (`[[getting started]]`) used everywhere else.
- The "Armira project example" link in `tutorial/Part 2` line 448 points
  at the repo root rather than a real path.
- Seven `📸 TODO:` placeholders remain in published pages (see top of
  audit). Six `📸 SCREENSHOT:` placeholders in `interface/` pages use a
  different syntax; pick one.
- Video references in
  [interface/the-grid/index.md](interface/the-grid/index.md) line 61 and
  [interface/the-grid/saved views.md](interface/the-grid/saved%20views.md)
  line 40 use `<source src="../../videos/...mp4">`. Confirm the relative
  path actually resolves under Quartz's build (Quartz rewrites links — a
  raw `<video>` may not).

### Code fences and tables

- Code fences are consistent (` ```python title="..." `, ` ```yaml `,
  ` ```bash `, ` ```json `). No drift detected.
- Tables use both pipe-padded (`| Field | Type | ... |`) and tight
  (`|Field|Type|...|`) styles within the same file in a couple of
  places — minor cosmetic.

## Pipeline notes

The May 2026 cleanup PR repeatedly conflicted on
`content/reference/CLI Commands.md` and
`content/features/data-pipeline/serializers.md`. Plausible reasons:

- **CLI Commands.md** has multiple unrelated "everyday / testing /
  keycloak / database / AI" sections that are independently edited by
  human PRs and the auto-update bot. Recommendation: split the AI
  command block into its own page (`reference/AI Commands.md`) and have
  the auto-update bot only touch a single canonical surface per command.
- **serializers.md** has had three recent additions stacked into a
  single page (`DEFAULT_SERIALIZER_NAME`, history-tables override note,
  `id`-always-present note). Adding stable section anchors
  (`{#default-serializer-name}`, `{#id-field-always-present}`,
  `{#history-tables-pickup}`) gives the bot's diff something to target
  cleanly.

Other recommendations for the next pipeline iteration:

- Have `copilot_docs_pr_gate.yml` also fail when a PR introduces a
  `📸 TODO:` comment. The current set has been re-introduced twice.
- Add a frontmatter-presence check (already partly done in the gate at
  line 11–12); extend it to fail when a `.md` file under `content/` is
  missing a `title:` — would catch the PFE-file regression.
